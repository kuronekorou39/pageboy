# pageboy 設計メモ

## 解いている問題

横長モニタでページ漫画を横幅フィットすると、1 ページが画面に収まらない(B5 比率のページで約 40% しか見えない)。
「少し下へスクロール → 次ページ → また上から」を繰り返すのが面倒で、既存のスライドショーはページ単位でしか送れない。

調査(2026-10)の結果、コマ検出つきの Guided View 風リーダーはいくつかあるが、
「ローカル画像フォルダを、ページ内スクロール込みで自動的に送る」ものは商用・OSS ともに見当たらなかった。

## 基本モデル

### ステップ

ページを横幅フィット(× 拡大率)で描いたときの高さを `H`、画面高さを `V` とする。
`H <= V` ならステップは 1 つ。それ以外は、移動量 `T = H - V` を
`stride = V × (1 - overlap)` で割って切り上げた数 + 1 をステップ数 `n` とし、
オフセットは `T × i / (n - 1)` で等分する(最後だけ短くならないようにする)。

`overlap` は既定 0.15。前のステップの下端が次のステップの上端に少し残るので、途中で切れたコマを見失わない。

### カーソル

`{ work, page, step }`。`step` は `Infinity` を「そのページの最後のステップ」の意味で使う
(前のページへ戻るとき、画像を読む前にステップ数が分からないため。描画時に実際の数へ clamp する)。

### 進む / 戻る

| 操作 | 順番モード | ランダムモード |
|---|---|---|
| 進む | 次ステップ → 次ページ先頭 → 次作品先頭 → 終端で停止 | 次ステップ → 同じ作品内のランダムなページ |
| 戻る | 前ステップ → 前ページ末尾 → 前作品末尾 | 前ステップ → 履歴を 1 つ戻る |

ランダムは「袋」方式(ShuffleBag)。全ページを引き切るまで同じページは出ない。直前のページとも重ねない。

### 連続モード(strip)

作品の全ページを縦に 1 本につなげ、ページの間に 16px の黒い帯を挟んで、画面高さ × (1 - overlap) ずつスクロールする。
ページ送りモードと違い、ページの末尾で「次ページの先頭へ戻る」動きがない。

- レイアウトは全ページの縦横から先に計算する。縦横は Rust がヘッダだけ読んで返す(`page_sizes`)ので、画像本体を読む前に帯の長さが決まる
- 描画するのは画面の前後 1 画面ぶんにかかるページだけ(`visiblePages`)
- 「いま見ているページ」は画面中央にかかるページ(`pageAtScroll`)。HUD と lastPage の保存に使う
- 拡大率や画面サイズが変わったときは、ページ内の相対位置を保って位置を移す(`rescaleScroll`)
- 順番モードの作品にだけ使う。ランダムモードの作品はページ送りで動かす(ランダムに選んだページを帯にする意味がない)
- 末尾まで行ったら次の作品の先頭へ。先頭で戻れば前の作品の末尾へ

### 自動再生

一定間隔で「進む」を呼ぶだけ。間隔は画像が表示されてから数える(読み込み待ちは含めない)。
手動操作をするとタイマーをリセットする。終端に達したら止まる。

### ライブラリ

開いたフォルダの中を深さ 3 まで走査し、画像を直接含むフォルダをそれぞれ 1 作品とする。
開いたフォルダ自体が画像を含むなら、それも 1 作品。並びはファイル名の自然順(数字を数値として比較)。

作品の作者と題名はフォルダ名から読む(`parseWorkName`)。置き方の規則は `library/README.md` にまとめてある。

- フォルダ名が `[作者] 題名` なら角括弧の中が作者、残りが題名
- そうでなければ親フォルダ名が作者。親がライブラリのルートなら作者なし
- タグやメタデータファイルは持たない。ユーザーにタグ付けを強いないため、フォルダ名だけで動く範囲に留める

作品ごとのモード(順番 / ランダム)と最後に読んだページは、作品のパスをキーに設定へ保存する。

## 設定ファイル

`data/settings.json`(開発中はリポジトリ直下。インストール版は `%APPDATA%/com.rou39.pageboy/data/`。`PAGEBOY_HOME` で変更可)

```jsonc
{
  "version": 1,
  "intervalMs": 4000,
  "zoom": 1.0,          // 1 = 横幅フィット
  "overlap": 0.15,
  "viewMode": "page",   // page | strip
  "lastLibrary": "D:/manga",
  "lastWork": "D:/manga/作品A",
  "folders": {
    "D:/manga/作品A": { "mode": "sequential", "lastPage": 12 },
    "D:/illust":      { "mode": "random",     "lastPage": 0 }
  }
}
```

## Rust コマンド

| コマンド | 役割 |
|---|---|
| `app_info()` | データ置き場(home)、設定ファイル、既定ライブラリのパス |
| `scan_library(root)` | フォルダを走査して作品とページのパス一覧を返す(並べ替えは TS 側) |
| `read_image(path)` | 画像ファイルをバイト列で返す(拡張子が画像のものだけ) |
| `page_sizes(paths)` | ヘッダだけ読んで各画像の縦横を返す(連続モード用) |
| `load_settings()` / `save_settings(json)` | 設定ファイルの読み書き。内容の検証は TS 側 |
| `startup_args()` | 起動引数。フォルダパスが渡されていればそれを開く |

## 今後の拡張候補(優先順)

1. 作品をまたぐ順番もランダムにする(ライブラリ単位の shuffle)。作者や題名の `(補足)` で絞った範囲でのランダム再生もここに含める。作品一覧を 1 キーで開いて文字で絞り込み、ジャンプする画面が入口になる
2. ステップ境界をコマ間の余白(横一列の白い帯)へ吸着させる。画像の行ごとの白率を見るだけなので安価。連続モードでも同じ考え方が使える
3. 滞在時間をステップ内の情報量(黒画素の密度、文字の多さ)で伸縮させる
4. ZIP / CBZ を Rust 側で展開して同じ Work として扱う
5. 見開き(横長画像)の扱い。2 ページ分なら右半分 → 左半分の順に横へステップする
6. コマ検出(Kumiko 方式の OpenCV)を「視点」の候補として差し込む。やるとしても別レイヤーにして、ステップ方式はそのまま残す
